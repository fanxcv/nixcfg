# nixcfg 维护手册

本仓库一切由 Nix 声明：**改配置 = 改 nix 文件**。本手册回答三个问题：改哪里、怎么验、出问题怎么查。

---

## 0. 心智模型

### 0.1 两个「单一事实源」

| 单一源 | 管什么 | 派生到 |
|---|---|---|
| `tools/machines.nix` | 机器注册（16 台） | `homeConfigurations` / `darwinConfigurations` / `nixosConfigurations` / `nix run .#<机>` 别名 |
| `modules/home/vscode-extensions.nix` | VSCode 扩展清单（22 条） | 客户端三 profile 扩展 / vscode-server 扩展 / unfree 白名单 |

**加机器、加插件只改这两个文件**，其余全部自动派生。

### 0.2 目录职责

| 目录 | 职责 |
|---|---|
| `flake.nix` | 唯一入口：inputs、构造器（mkHomeConfig / mkDarwinConfig / mkNixosConfig）、outputs、checks |
| `tools/machines.nix` | 机器注册表（纯数据） |
| `tools/config.nix` | 镜像源 / GitHub 代理 / RustDesk 等**唯一配置源** |
| `tools/scan.nix` | 目录扫描规则（见 §3.1） |
| `tools/sshUserKeys.nix` | 机器 SSH 身份公钥清单（授权下发的单一事实来源） |
| `home/fan/` | 用户层（Home Manager）：`_common_`（全平台）→ `_<platform>_` → `<机>`，由 `module-list.nix` 组装 |
| `hosts/` | 系统层（仅 darwin / NixOS）：`_darwin_` / `_nixos_` / `<机>` |
| `modules/home/` | 可复用模块库（vscode / codex / pi / ssh / tmux / ai / mise…） |
| `overlays/` | 3 个 overlay：`unstable` / `vscode`（扩展市场）/ `skemate` |
| `packages/` | 本地自打包（kasmvnc / rustdesk-bin / mcmojave-circle / catppuccin-konsole） |
| `tests/` | 门禁脚本（见 §2.1） |
| `docker/ide/` | 开发容器 compose 与 Dockerfile |
| `pve/` | PVE 宿主：render / mkHost / deploy / apply |
| `secrets/` | age 加密件 + `encrypt.sh` + `keys.nix`（接收者公钥） |

### 0.3 包来源四路

| 来源 | 引用 | 用途 |
|---|---|---|
| nixpkgs 主仓（26.05） | `pkgs.<name>` | 绝大多数软件 |
| unstable 通道 | `pkgs.repos.unstable.<name>` | 仅 4 处：vscode 本体（NixOS）、qq、codex、remote-ssh 扩展（旧版 macOS socket 路径超限致重连） |
| VSCode 扩展主市场 | `pkgs.vscode-extensions.<pub>.<name>` | 扩展主体 |
| VSCode 扩展补市场 | `pkgs.repos.vscode.vscode-marketplace-release.<pub>.<name>` | nixpkgs 缺失项（autopep8 / vscode-buf / csv-grid-editor / pencildev） |
| VSCode 扩展 unstable 通道 | `pkgs.repos.unstable.vscode-extensions.<pub>.<name>` | 主通道版本有已知缺陷时（现仅 remote-ssh） |
| 本地自打包 | `pkgs.<包名>`（`packages/`） | nixpkgs 无此包 |

**禁止本地自打包 VSCode 扩展**（扩展一律走三个市场：主市场 / 补市场 / unstable 通道）。

## 1. 常见操作

### 1.1 加一个普通软件（nixpkgs 已有包）

| 范围 | 落点 |
|---|---|
| 全平台通用 | `home/fan/_common_/base.nix` 的 `home.packages` |
| 仅某平台 | `home/fan/_linux_/base.nix`（或 `_darwin_/` 对应文件） |
| 仅某台机器 | `home/fan/<机>/apps.nix` |

- unfree 包额外改 `flake.nix` 的 `unfreeAllowlist`（填 `lib.getName` 匹配名，通常是 pname）
- 验证：`nix eval .#homeConfigurations."fan@<机>".config.home.packages --apply 'ps: builtins.map (p: p.pname or p.name) ps'`

### 1.2 加一个需要配置的软件（模块）

新建 `modules/home/<名>.nix`：

```nix
{ config, lib, pkgs, ... }:
let cfg = config.softwares.<名>;
in {
  options.softwares.<名>.enable =
    lib.mkEnableOption "<名>" // { default = true; };   # 默认开；默认关则去掉 // {...}
  config = lib.mkIf cfg.enable { /* home.packages / 配置文件 / activation */ };
}
```

- `tools.scan` 自动导入 `modules/home/*.nix`，**无需注册**
- 某台机器关闭：`softwares.<名>.enable = lib.mkForce false;`（放机器层）
- 验证：`nix eval .#homeConfigurations."fan@<机>".config.softwares.<名>.enable`

### 1.3 加一个自打包软件

1. 新建 `packages/<名>.nix`（平铺文件**自动注册**，无需改 `packages/default.nix`）
2. 特例才需动 `packages/default.nix` 的 `explicitFiles`：平台限定（如 kasmvnc 仅 linux、rustdesk-bin 仅 x86_64-linux）或需额外参数（如 `packages/catppuccin/konsole.nix` 要 `githubFetchBase`）
3. 验证：`nix build .#<名>` + `nix eval --json .#packages.aarch64-darwin --apply builtins.attrNames`

### 1.4 加一个 VSCode 插件

**只改 `modules/home/vscode-extensions.nix`**，加一条记录：

```nix
{
  id = "publisher.name";
  pkg = pkgs: pkgs.vscode-extensions.publisher.name;        # 主市场；主通道版本有缺陷才用 pkgs.repos.unstable.vscode-extensions.publisher.name
                                                             # 或 pkgs.repos.vscode.vscode-marketplace-release.publisher.name（补市场）
  profiles = [ "default" "python" "go" ];                    # 进哪些客户端 profile
  client = true;                                             # 装客户端
  server = true;                                             # 装 vscode-server 端（纯 UI 类置 false）
  unfree = "vscode-extension-publisher-name";                # 可选，仅 unfree 扩展；自动进 flake.nix 白名单
}
```

- 无需改 `vscode.nix` / `flake.nix`
- 验证：
  ```bash
  nix eval --json '.#darwinConfigurations.mba-m5.config.home-manager.users.fan.programs.vscode.profiles' \
    --apply 'p: builtins.mapAttrs (n: v: map (x: x.vscodeExtUniqueId) v.extensions) p'
  ```

### 1.5 加一台机器

1. `tools/machines.nix` 加一条：

```nix
<机名> = {
  kind = "darwin";        # darwin | nixos | container | ubuntu | pve
  system = "aarch64-darwin";
  user = "fan";           # 输出键为 "<user>@<机名>"
  alias = true;           # 生成 nix run .#<机名>
  extraUnfree = [ ];      # 可选
};
```

2. 建机器目录：`home/fan/<机>/default.nix`（HM 差异）；darwin/nixos 另加 `hosts/<机>/`
3. secrets：`secrets/keys.nix` 加 age 公钥 + 建 `secrets/hosts/<机>/`
4. 机器 SSH 身份（需该机能登录各机时）：生成密钥对 → 公钥入 `secrets/hosts/<机>/ssh-user-key.pub`，
   私钥入 `secrets/source/hosts/<机>/ssh-user-key` 后跑 `./secrets/encrypt.sh`，再把 `<机>` 加入 `tools/sshUserKeys.nix` 的 hosts
5. 验证：`nix flake check`（`machine-sets` 会断言输出键集）+ `nix run .#<机名>`

### 1.6 加一个 secret

1. 明文放 `secrets/source/<名>`（已 gitignore）
2. 跑 `./secrets/encrypt.sh` → 生成 `secrets/<名>.age`（公共）或 `secrets/hosts/<机>/<名>.age`（机器独有）
3. 消费：在 `home.activation` 里用 `${pkgs.age}/bin/age -d -i "$HOME/.secrets/age-keys.txt" -o <目标> <secrets/*.age>`（模式见 `home/fan/_common_/secrets.nix`）
4. 部署后验证目标文件存在

### 1.7 改镜像源 / 代理

1. 改**唯一源** `tools/config.nix`
2. 同步手写副本（门禁会强制）：`flake.nix` 的 `nixConfig`、`docker/ide/ubuntu/Dockerfile`、`docker/ide/ubuntu/entrypoint.sh`、`pve/deploy.sh`、`pve/apply.sh`（registry mirrors）
3. 验证：`nix flake check`（`mirror-consistency` 逐项断言）
4. GitHub 加速前缀另有 `tools/config.nix` 的 `githubProxy` + `scripts/switch-github-proxy.sh`

### 1.8 加 / 改一个门禁

1. 脚本放 `tests/`（风格对齐 `tests/mirror-consistency.py`）
2. 挂进 `flake.nix` 的 `checks`
3. **必须给反例证据**：临时篡改输入 → check 必须失败（证明不是橡皮图章）
4. 验证：`nix build .#checks.aarch64-darwin.<名>`

## 2. 验证与部署

### 2.1 `nix flake check` 的 6 项门禁

| check | 管什么 | 失败说明 |
|---|---|---|
| `formatting` | treefmt（nixfmt + statix） | 有文件未格式化 → `nix fmt` |
| `mirror-consistency` | 镜像源 5 处 + docker registry mirrors | 手写副本与 `tools/config.nix` 漂移 |
| `machine-sets` | 输出键集 == 冻结基线（11/3/2）+ 别名 14 个 | `tools/machines.nix` 与输出不符 |
| `eval-all-targets` | 16 个目标全部可求值 | 某机器配置求值失败 |
| `scan-imports` | 无被静默跳过的 `.nix` | 有文件埋进无 `default.nix` 的子目录 |
| `rustdesk-injector` | RustDesk 注入器回归 | injector 与测试脱节 |

**一键验证：`nix flake check`**（应输出 `all checks passed!`）

### 2.2 常用查询命令

```bash
# 机器清单
nix eval --json .#homeConfigurations --apply builtins.attrNames
nix eval --json .#darwinConfigurations --apply builtins.attrNames
nix eval --json .#nixosConfigurations --apply builtins.attrNames

# 某机某软件是否启用
nix eval '.#homeConfigurations."fan@ide-si".config.softwares.ssh.enable'

# 某机 VSCode 扩展
nix eval --json '.#darwinConfigurations.mba-m5.config.home-manager.users.fan.programs.vscode.profiles' \
  --apply 'p: builtins.mapAttrs (n: v: map (x: x.vscodeExtUniqueId) v.extensions) p'

# 容器 server 端扩展
nix eval --json '.#homeConfigurations."fan@ide-si".config.home.file.".vscode-server/extensions".source.paths' \
  --apply 'map (p: p.vscodeExtUniqueId)'

# 自打包包集合
nix eval --json .#packages.aarch64-darwin --apply builtins.attrNames

# 格式检查（不写盘）
nix fmt -- --ci
```

### 2.3 部署

| 目标 | 命令 |
|---|---|
| 任意机器（HM / darwin / 容器 / PVE） | `nix run .#<机名>`（一步构建 + 激活；darwin 走 `sudo .../activate`） |
| NixOS 真机 | `sudo nixos-rebuild switch --flake /etc/nixos#<机名>`（无 `nix run` 别名） |
| PVE 宿主 | 见 `pve/deploy.sh` |

### 2.4 改动影响面

- 改 `_common_` / `modules/` / `tools/config.nix` → 影响全部平台
- 改 `_<platform>_` → 影响该平台
- 改 `home/fan/<机>` / `hosts/<机>` → 仅该机
- **不再需要人工判断验证目标**：`nix flake check` 已 eval 全部 16 个目标，改完直接跑它

## 3. 约定与坑

### 3.1 `tools.scan` 扫描规则（硬规矩）

- 只导入「直接子 `.nix` 文件（除 `default.nix`）」或「含 `default.nix` 的子目录」
- **无 `default.nix` 的嵌套目录被静默跳过**（不报错）→ 由 `scan-imports` 门禁兜底
- scan 目录内禁止放需要 import 传参的模块（只能吃 specialArgs）
- 导入顺序 = 字典序，勿依赖顺序（要顺序请用显式 `imports`）

### 3.2 激活脚本规范

- **系统工具**（sudo/launchctl/pkill/open/pgrep/sleep/cat/find/readlink）裸命令即可（`path.nix` 已补 PATH）
- **nix 工具**（python3/age/git/curl/gnused…）必须 `${pkgs.xxx}/bin/xxx` 绝对路径
- 失败策略：禁静默吞错；`|| true` 只允许幂等检查且必须注释原因；非关键失败 `echo "警告: ..."`；前置失败导致无法继续则直接失败
- 变量后紧跟全角标点会被 bash 吞进变量名 → 必须加空格（`$var ，`）
- root 域操作（LaunchDaemon / 跨用户进程）放 `system.activationScripts`

### 3.3 flake 解析期限制

| 限制 | 后果 | 应对 |
|---|---|---|
| `nixConfig` 在解析期读，不能 import `tools/` | 镜像配置必须手写副本 | 靠 `mirror-consistency` 门禁 |
| `inputs.url` 必须是字符串字面量 | GitHub 代理前缀无法从 `tools/config.nix` 读 | 改前缀跑 `scripts/switch-github-proxy.sh` |
| `unfreeAllowlist` 在 pkgs 构造时求值 | 不能在模块里生成 | 由 `vscode-extensions.nix` 静态 `unfree` 字段生成 |

### 3.4 secrets 架构（无兜底链）

- fan 域：`home.activation` 里 `age -d`，**失败即部署失败**（无 `|| true`）
- 系统域（NixOS host keys）：走 agenix 系统层
- 禁止：HM 层 `age.secrets` 声明、任何"解密失败就跳过"的兑底
- 命名：公共 → `secrets/<名>.age`；机器独有 → `secrets/hosts/<机>/<名>.age`

### 3.5 SSH 访问与加固（分层）

密码类认证一律关闭（`PasswordAuthentication` + `KbdInteractiveAuthentication`；Ubuntu 默认 `UsePAM yes`，只关前者不够）。

| 平台 | 落点 |
|---|---|
| NixOS 真机 | `hosts/_nixos_/services/openssh.nix`（`services.openssh.settings`） |
| macOS | `hosts/_darwin_/base/ssh.nix`（`extraConfig` → `sshd_config.d/100-nix-darwin.conf`） |
| 容器 / 云服务器 | `modules/home/ssh.nix` 激活脚本 → `sshd_config.d/00-nix-hardening.conf` |
| PVE 宿主 | 不在范围内（脚本对 `platform = "pve"` 提前 return） |

- **Ubuntu/Debian 写 `00-` 前缀 dropin**：主 `sshd_config` 顶部 `Include sshd_config.d/*`，cloud-init 的 `50-cloud-init.conf` 会把 `PasswordAuthentication` 设回 `yes`，而 sshd 取「首次出现的值」→ 追加到主文件末尾或写 `50-` 之后均无效
- OpenSSH 9.8+ 已移除 `ChallengeResponseAuthentication`，写入会让 `sshd -t` 失败，改用 `KbdInteractiveAuthentication`
- **机器身份清单 = `tools/sshUserKeys.nix`**：持有身份私钥（`secrets/hosts/<机>/ssh-user-key.*`）因而可登录各机的机器都在此列表；NixOS 与 mac 在 nix 层授权，容器/云服务器靠激活脚本下发
- mac 身份解密为 `~/.ssh/id_rsa`，nix-lenovo / nix-asus / nix-im 为 `~/.ssh/id_ed25519`
- mac 上 `services.openssh.enable = true` 激活时调 `systemsetup` 读远程登录状态，SSH 会话下可能被 TCC/完全磁盘访问拦住 → 改用图形会话部署或给远程用户授予完全磁盘访问

### 3.6 NixOS 共享服务（三台真机一致）

`home/fan/_nixos_/` 下的模块被三台 NixOS 真机自动继承（`tools.scan`），行为无需逐机声明：

| 服务 | 落点 | 行为 |
|---|---|---|
| mihomo 代理 | `mihomo.nix` + `mihomo/` 子目录 | 开机自启（linger）；激活期生成配置；`mihomo-refresh.timer` 开机后 1min ＋ 每日 04:17 重拉订阅并重启内核 |
| syncthing | `syncthing.nix` | 系统级服务（user=fan）；设备互配清单 `tools/syncthingPeers.nix`；`~/sync`（仅现有机器之间）与 `~/share`（含三个 ide 容器）持久化见 `_nixos_/immutable.nix` |
| 微信 / QQ | `modules/home/chat.nix` | `softwares.chat.enable` 默认 `platform == "nixos"`；某台不装则机器层 `lib.mkForce false` |

- **新增机器**：syncthing 需把其 device ID 加进 `tools/syncthingPeers.nix`（ID 取真机 `~/.local/state/syncthing/config.xml` 的 `<device id=`）：现有机器与 Mac 进 `peers`（sync+share），ide 容器进 `idePeers`（仅 share）
- **同步目录划分**：`~/sync` = `peers`（现有机器之间）；`~/share` = `peers + idePeers`（含 ide-si / ide-lenovo / ide-mac）。三个 ide 容器只建 `share`，不建 `sync`（见 `home/fan/_container_/syncthing.nix`）；容器侧 syncthing 以 fan 运行，同步目录就是桌面上的 `/home/fan/Desktop/share`（fan 属主，桌面会话可直接读写）
- **ide 容器接入（双阶段）**：① 部署容器（先 `docker compose up -d` 重建以生效 compose 新增挂载 `./share`、`./syncthing/{config,state}`（三者均挂 fan 侧：`/home/fan/Desktop/share`、`/home/fan/.config/syncthing`、`/home/fan/.local/state/syncthing`），再容器内 `nix run .#ide-<机>`）→ ② 容器内 `ssh` 读 `/home/fan/.config/syncthing/config.xml` 的 `<device id="...">`，回填 `tools/syncthingPeers.nix` 的 `idePeers` → 各机下次部署自动互配；容器无 tailscale，地址仅 `dynamic`（全局发现/中继）
- **mihomo 订阅更新**：激活期只跑一次，重启不重拉 → 靠 `mihomo-refresh.timer`；若发现代理节点过期，`systemctl --user start mihomo-refresh` 手动触发
- **mihomo API 不监听（9090 Connection refused）**：多为启动竞态（旧实例未释放端口时 bind 失败被静默跳过），`systemctl --user restart mihomo` 即自愈

### 3.7 提交与推送

- commit message 中文，格式 `scope: 简述`
- 提交前看 `git status` 与 `git diff`；一事一改，不夹带生成物与凭据
- **禁自动 push**；force push / reset --hard / 删分支先报后动

## 4. 排查手册

| 症状 | 定位与处置 |
|---|---|
| `nix flake check` formatting 失败 | `nix fmt`（纯格式化，单独提交） |
| `machine-sets` 失败 | `tools/machines.nix` 与实际输出键集不符；`nix eval .#homeConfigurations --apply builtins.attrNames` 对照 |
| `eval-all-targets` 失败 | 某机器配置求值报错，按输出里的目标名定位 |
| `scan-imports` 失败 | 有 `.nix` 埋在无 `default.nix` 的子目录里 → 给它补 `default.nix` 或移到平铺层 |
| `mirror-consistency` 失败 | 手写副本与 `tools/config.nix` 漂移，按错误里列出的差异逐项对齐 |
| darwin 上 `nix eval .#packages` 报平台不支持 | 该包需 `lib.optionalAttrs hostPlatform.isLinux` 包住（参考 kasmvnc / rustdesk-bin） |
| VSCode 插件不生效 | 查 `vscode-extensions.nix` 那条的 `client` / `server` / `profiles` 字段；改完重启 VSCode |
| 软件没装 | 查模块 option 默认值与机器层是否有 `mkForce false`：`nix eval .#homeConfigurations."fan@<机>".config.softwares.<名>.enable` |
| 部署失败 | 看 activation 报错；多半是 secrets 解密（无兜底，必失败）或绝对路径缺失 |
| 改了 nix 却不生效 | 文件是否在 scan 目录且被导入？跑 `nix flake check` 的 `scan-imports` 确认 |
| Ubuntu 容器/服务器密码登录仍可用 | 开关必须写 `sshd_config.d/00-` 前缀 dropin（cloud-init 抢先），且 `PasswordAuthentication` 与 `KbdInteractiveAuthentication` 要同关 |
| mac 上 `sudo darwin-rebuild` 报 app 权限错误 | nix-darwin 的 App Management 预检拦住 SSH 会话，改用图形会话或给远程用户授予完全磁盘访问 |
| 某机能登录自己但登不进其他机器 | 目标机未部署新配置（`/etc/ssh/nix_authorized_keys.d/` 或 `authorized_keys.d/` 缺失）；先在该机跑一次部署 |
| NixOS 代理节点全过期 | `systemctl --user start mihomo-refresh`（或等每日 04:17 timer） |
